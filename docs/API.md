# API Reference

## Base URL
- Local: `http://localhost:8000`
- Production: set via `VITE_API_BASE_URL` env var in the frontend

---

## GET /
Health ping. Returns `{ "message": "..." }`.

## GET /health
Returns `{ "status": "ok" }`. Use for uptime monitoring / deployment health checks.

---

## POST /api/analyze

Analyze a pasted medical report and return a structured plain-language explanation.

### Request body
```json
{
  "report_text": "<paste full report text here>",
  "report_type": "radiology | lab | pathology | clinical | discharge | other"
}
```

| Field         | Type   | Required | Notes                          |
|---------------|--------|----------|--------------------------------|
| `report_text` | string | ✅       | Min 1 character                |
| `report_type` | string | ✅       | Used in fallback summary prose |

### Response body
```json
{
  "summary": "Plain-language summary of the report.",
  "key_findings": ["finding 1", "finding 2"],
  "recommendations": ["next step 1", "next step 2"],
  "disclaimer": "This information is for education only...",
  "source": "hf_inference | local_model | fallback",
  "parse_warning": false
}
```

| Field           | Type     | Notes                                                                 |
|-----------------|----------|-----------------------------------------------------------------------|
| `summary`       | string   | If parsing failed, value is `"Summary unavailable from model response."` |
| `key_findings`  | string[] | Comma/semicolon-split from model output                               |
| `recommendations` | string[] |                                                                    |
| `disclaimer`    | string   | Defaults to the standard safety notice if not found in model output   |
| `source`        | string   | `hf_inference` = HuggingFace API; `local_model` = local weights; `fallback` = keyword scan |
| `parse_warning` | boolean  | `true` when the model output could not be parsed into a summary — treat results with extra caution |

### `source` values explained

| Value          | Meaning                                                        |
|----------------|----------------------------------------------------------------|
| `hf_inference` | Response generated by the HuggingFace Inference API            |
| `local_model`  | Response generated by a locally-loaded model checkpoint        |
| `fallback`     | Model call failed or returned nothing; keyword scan was used   |

### `parse_warning` flag

Set to `true` when `parse_structured_response()` could not extract a summary from the model output (e.g. the model used a different label like `"Overview:"` instead of `"Summary:"`). The frontend displays a yellow warning banner in this case. **Always cross-reference with a clinician when this flag is true.**

---

## Error responses

| Status | Meaning                                    |
|--------|--------------------------------------------|
| `422`  | Validation error — missing or empty fields |
| `500`  | Unhandled server exception                 |

Note: a parse failure is **not** a 4xx/5xx. It returns `200` with `parse_warning: true`. This is by design to keep the UI functional, but the frontend must surface the warning clearly.
